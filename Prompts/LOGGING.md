# LOGGING.md — протокол ведения журнала работы

Журнал — единственный доказательный документ работы агента.
Отчёт в чате без записи в LOG.md считается незавершённой работой.

## Правила

1. Журнал ведётся в файле LOG.md в корне репозитория.
2. Записи только ДОБАВЛЯЮТСЯ в конец файла. Редактировать и удалять
   ранее сделанные записи запрещено.
3. Запись делается сразу после выполнения команды, до ответа в чат.
4. Ничего не выдумывать: если проверка не запускалась — так и писать
   «не проверял», а не «должно работать».
5. В журнал не записывать личные данные и содержимое сейв-файлов —
   только имена файлов и факты.

## Формат записи (обязательные поля)

```
## [Фаза N] ГГГГ-ММ-ДД ЧЧ:ММ — <короткое название задачи>
- Что сделано: <список файлов и изменений>
- Запуск и проверка: <точные команды, фактический вывод или скрин>
- Что НЕ сделано / НЕ проверено: <список или «нет»>
- Файлы вне задания: <список или «не трогал»>
- Блокеры: <что мешает или «нет»>
```

## Особые требования по фазам

- **Фаза 1 (гейт):** к записи прилагается фактический вывод
  tests/breeder.test.html — доли распределений 3:1, 1:1, 9:3:3:1
  с отклонениями в процентах. Без вывода тестов фаза не считается
  выполненной.
- **Фаза 3:** к записи прилагается результат проверки восстановления
  после перезагрузки и результат импорта повреждённого файла.

## Чего делать нельзя

- Писать «все тесты прошли» без приложенного вывода.
- Помечать фазу выполненной при открытых блокерах.
- Переписывать историю журнала.
