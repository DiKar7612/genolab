# Фаза 5 — Предсказатель и полировка

Прочитай genolab_tz.md (разделы 3.4 и 7), LOG.md и docs/api.md.

Реализуй:
1. Экран «Предсказатель» (раздел 3.4 ТЗ): игрок выбирает двух
   родителей, вводит свой прогноз вероятности нужного фенотипа;
   сверка с pennettGrid(); при ошибке — разбор решётки с подсветкой,
   где игрок ошибся. Счётчик точности прогнозов в store.js.
2. Полировка: плавные переходы экранов, hover/active-состояния кнопок,
   тосты вместо alert, фокус-стили для клавиатурной навигации.
3. Тач-адаптив: интерактивные элементы минимум 44x44px, модалки
   закрываются свайпом и по клику на фон.
4. Accessibility: aria-метки на кнопках, логичный порядок фокуса.
5. Убери все заглушки и console.log.

Критерии — только измеримые, проверь каждый сам через chrome-devtools
и запиши ФАКТИЧЕСКИЕ числа в LOG.md (не выдуманные):
1. Grep по проекту: alert( и console.log( — 0 вхождений в js.
2. evaluate: все кнопки имеют aria-label или непустой текст —
   перечисли исключения, если есть.
3. evaluate: вычисли контраст цветов текста/фона по WCAG-формуле
   для 5 основных сочетаний палитры — покажи числа; все ≥ 4.5.
4. navigate + замер: время от открытия до интерактивности (performance
   trace) — запиши фактическое число секунд.
5. Скриншоты всех пяти экранов при ширине 360px.
6. E2E: пройди «предсказание → сверка → разбор ошибки» для заведомо
   неверного прогноза — разбор показывается.

Lighthouse запускает пользователь — не отчитывайся его числами.
Критерий готовности: все 6 пунктов выше проверены с фактическими
числами в LOG.md; визуальную приёмку и Lighthouse выполняет
пользователь.
