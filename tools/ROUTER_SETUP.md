# ROUTER_SETUP.md — роутер моделей для Pi-Cli (llama-swap)

## Что это даёт

Pi-Cli работает с одной моделью (qwen3.8-27b, текстовая). Скриншоты она
читать не может («does not support images»). Решение: локальный роутер
llama-swap на едином адресе, за которым две модели:

- `main`   — qwen3.8-27b (текстовая, основная модель агента)
- `vision` — Qwen2.5-VL-3B-Instruct (мультимодальная, смотрит картинки)

Роутер сам поднимает нужный llama-server по имени модели и **выгружает
неиспользуемый** — процесс завершается, RAM и VRAM освобождаются целиком.

Переключение не мгновенное:
- `vision` (3B) поднимается за 10–15 с;
- `main` (27B) — за 30–90 с.

## TTL (время жизни модели после последнего запроса)

- `vision`: **120 сек** — выгрузка через 2 минуты после последнего
  vision-запроса. После паузы >2 мин первый vision-запрос может занять
  до 15 с (подъём модели) — это норма, не сбой.
- `main`: 3600 сек — 27B держится час. Если хотите и здесь 120, учтите:
  подъём 27B за 30–90 с после каждой двухминутной паузы почти наверняка
  обойдётся дороже, чем держать её в VRAM.

Правило для агента (важно): vision-проверки делать **пачкой** — один
вызов `vision_check.py` на все скриншоты шага, не по одному на действие.

## Установка (один раз)

1. Скачайте llama-swap (один exe, релизы на GitHub: github.com/mostlygeek/llama-swap)
   и положите в `F:\genolab\tools\llama-swap.exe`.
2. Откройте `F:\genolab\tools\swap_config.yaml` и впишите 3 плейсхолдера:
   - `<LLAMA_SERVER_EXE>` — путь к llama-server.exe;
   - `<GGUF_27B>` — путь к gguf вашего qwen3.8-27b;
   - GGUF VL-3B и mmproj уже прописаны (модели из
     `D:\Voise-to-text_Agent_V1\Chat_Mobile\models\Qwen2.5-VL-3B-Instruct-Q4_K_M`).
3. Проверьте порт 8080 свободен: `netstat -ano | findstr :8080`.
   Если занят — поменяйте порт в swap_config.yaml, start_router.bat,
   vision_check.py и в настройке Pi (одно и то же число везде).
4. Запуск: `F:\genolab\tools\start_router.bat`.
   Проверка: `curl http://127.0.0.1:8080/v1/models` — в списке main и vision.

## Настройка Pi-Cli

В настройке модели Pi-Cli:
- Эндпоинт (OpenAI-compatible): `http://127.0.0.1:8080/v1`
- Модель: `main`
- Ключ API: любой (например, `none`) — роутер его не проверяет

После этого Pi-Cli снова отвечает через qwen3.8-27b, но уже через роутер.

## Дополнить APPEND_SYSTEM.md

```
## Чтение изображений (vision)

Модель агента — текстовая, читать картинки напрямую НЕЛЬЗЯ (ответ-заглушка).
Все изображения — только через vision_check:

    python F:/genolab/tools/vision_check.py <путь_к_картинке> --preset ui
    (пресеты: ui | palette | layout360 | creature)

Работа с vision:
- Сначала все числовые проверки через evaluate в DOM (bbox, computed style,
  размеры) — точные величины vision не меряет.
- Потом ОДИН вызов vision_check на все скриншоты шага (пачкой), не по одному.
- После паузы больше 2 минут первый vision-запрос занимает до 15 секунд
  (роутер поднимает VL-модель) — это норма, повторных вызовов не требуется.
- Точные цвета/пиксели сверяй только по computed style из DOM;
  vision_check используй для состава экрана, палитры, целостности вёрстки.
```

## Проверка связки (первый прогон)

1. `start_router.bat` — роутер поднялся.
2. `python F:\genolab\tools\vision_check.py <любой png из Temp> --preset ui`
   — первый вызов ~15 с (подъём VL), дальше быстро.
3. Напишите Pi-Cli любое сообщение — роутер переключится на `main`
   (30–90 с при первом сообщении после выгрузки).
4. Если роутер не виден — проверьте, что llama-swap.exe запущен и порт
   совпадает во всех трёх файлах.
